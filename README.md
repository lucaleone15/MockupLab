# MockupLab

**Générateur de mock-ups 3D gratuit, open source et 100 % local.**
Glisse un screenshot, obtiens un rendu d'appareil réaliste — en 3D ou posé en perspective sur une vraie photo — et exporte-le en vraie image (PNG, JPG, WebP) jusqu'en 4K. Aucun serveur, aucun upload : tes images ne quittent jamais ton navigateur.

> *English summary: free, open-source, in-browser 3D mock-up generator. Drop a screenshot, get a photoreal device render, export PNG/JPG/WebP up to 4K. No backend, no upload. UI available in French and English.*

## Démarrer

Prérequis : Node.js 20+.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # build de production dans dist/
npm run preview    # sert le build sur http://localhost:4173/MockupLab/
```

## Utilisation

1. Glisse une image sur la fenêtre, colle-la avec **⌘V / Ctrl+V**, ou clique sur **Essayer un exemple**.
2. Tourne autour de l'appareil (glisser), zoome (molette), déplace la vue (clic droit).
3. Pour changer d'appareil, utilise le menu **Changer** en haut de l'onglet *Appareil*, ou clique sur un modèle dans la bibliothèque (le bouton **+** l'ajoute à la scène au lieu de remplacer).
4. Règle la finition, la luminosité de l'écran, les reflets et le fond dans le panneau de droite.
5. Choisis format, résolution et ratio, puis **Exporter** (**⌘E / Ctrl+E**).

Astuce : exporte ton design au ratio natif de l'écran (affiché sous le nom de l'image, par ex. **1179 × 2556** pour Phone Pro, **3024 × 1964** pour Laptop 14, **1440 × 900** pour le navigateur). Les captures plus longues sont cadrées par le haut ; le curseur *Position* fait défiler le cadrage. Les réglages propres à chaque appareil (orientation, ouverture, encoche, thème du navigateur…) apparaissent dans la section *Appareil*.

### Mode photo

1. Bascule sur **Photo** dans la barre du haut.
2. Choisis une photo fournie dans la bibliothèque, ou **Importer ma photo** (écran, affiche, carte… prise en perspective).
3. Indique la zone : **double-clique** au milieu d'un écran ou d'une feuille pour la détecter, ou clique ses **4 coins** (touche **N**) — la loupe aide à viser au pixel près. Si la détection hésite, les autres propositions s'affichent en pointillés : clique celle qui convient (ou ◀ ▶, ou double-clique à nouveau). Glisse ensuite les coins ou les côtés, ou ajuste-les aux flèches (Maj : 10 px).
4. Glisse ton design sur la zone (ou colle-le). Règle la fusion dans le panneau de droite : *Reflets* pour un écran éteint (les reflets de la photo passent par-dessus ton design), *Ombres* pour du papier (plis, dégradés de lumière), *Premier plan* si des doigts ou un objet passent devant. *Surface d'origine* : en **Auto**, si la photo montre déjà quelque chose à cet endroit (écran allumé, affiche, texte), ce contenu est masqué et seule la lumière de la photo est gardée ; sur une surface vierge, ses reflets et ses détails passent sur ton design.
5. **Enregistrer comme modèle** pour réutiliser la photo et ses zones ; **Exporter** sort l'image à la résolution de la photo.

### Variantes et lots

- **Variantes** (bouton en haut, mode 3D) : choisis ce qui peut varier (décor, fond, lumière, angle, finition) et combien de variantes. Clique les aperçus pour les sélectionner ; survole-en un pour l'agrandir, **affiner** (des variations proches de celle-ci) ou l'**utiliser** comme scène. Avec deux sélectionnées, **Comparer** les met côte à côte. *Exporter* sort la sélection au format et à la taille de l'onglet Export (un ZIP s'il y en a plusieurs). Ta scène n'est jamais modifiée tant que tu ne cliques pas *Utiliser* (et ⌘Z revient en arrière).
- **Lot** (icône de calques en haut) : glisse plusieurs images ; chacune passe sur l'écran de l'appareil sélectionné (ou dans la zone sélectionnée en mode photo), avec la scène actuelle ou avec chacune des variantes sélectionnées. Tout part dans un ZIP.

### Vidéo

Dans l'onglet **Export**, choisis **Vidéo** : un plan cinéma (révélation, plongée dans l'écran, zoom en biais, pirouette, arrivée, grue, Vertigo, bande-annonce) ou une animation classique (rotation, balancement, travelling, défilement, flottement — défilement et zoom en mode photo), la qualité (*Cinéma* : flou de mouvement et profondeur de champ, plus lent ; *Rapide* pour un essai), sa durée, le format (MP4, WebM ou GIF), la taille et la cadence. **Aperçu** la joue en direct dans la vue (Échap pour l'arrêter) ; **Exporter la vidéo** (ou ⌘E) la calcule image par image puis la télécharge. Pour le défilement, importe une capture pleine page plus longue que l'écran.

## Comment ça marche

- **Rendu** : Three.js via react-three-fiber. Matériaux PBR (`MeshPhysicalMaterial` : métal anisotrope, verre, clearcoat, iridescence des objectifs), environnement studio généré à partir de *Lightformers* (aucun fichier HDR), tone mapping *Khronos PBR Neutral*.
- **Écran** : le shader d'écran sort du tone mapping et compose `image + Neutral(reflets)`. Les pixels de ton design sortent donc exactement avec leurs couleurs d'origine, tandis que les reflets suivent la même courbe que la vitre autour.
- **Géométrie** : contours en *squircle* (coins continus de type superellipse) balayés le long d'un profil d'arête, avec normales analytiques pour des reflets sans facettes (`src/lib/geometry`).
- **Matières réelles et table** : textures PBR et HDRI sous licence CC0 embarqués dans `public/assets/` (≈ 15 Mo, chargés à la demande). Le HDRI ne sert qu'à la lumière d'appoint et aux reflets (il n'est jamais affiché) ; sa fenêtre est détectée et tournée vers l'avant-gauche, d'où vient la lumière principale — un spot qui projette une texture (« gobo ») de fenêtre, de stores ou de feuillage sur le mur et la table.
- **Matières des appareils** : micro-surfaces procédurales (aluminium microbillé, titane brossé, verre dépoli) et légère variation de rugosité, pour casser l'aspect « image de synthèse ».
- **Kit de marque** : les polices importées restent dans le navigateur (API `FontFace`), sont enregistrées avec le projet et utilisables partout (calques, visuels générés, objets 3D).
- **Motifs graphiques** : générés par des shaders (`src/lib/patterns.ts`) dans un petit contexte WebGL dédié, à n'importe quelle résolution.
- **Éclairage** : chaque ambiance est un environnement procédural (*Lightformers*) + une lumière clé à ombres douces (VSM) ; l'environnement tourne avec la direction de la lumière pour garder des reflets cohérents.
- **Réflexion au sol** : miroir planaire avec plan de coupe oblique ; le reflet s'estompe selon la hauteur réelle du point reflété au-dessus du sol (lue dans la profondeur), comme sur une pierre polie.
- **Profondeur de champ** : modèle de lentille mince par accumulation (64 échantillons à l'export, progressif dans l'aperçu) — physiquement juste et compatible avec le rendu fidèle des écrans.
- **Mode photo** : homographie carré unité → quadrilatère (forme fermée de Heckbert) ; un shader WebGL2 renvoie chaque pixel de sortie dans le repère de la zone, échantillonne le design (mipmaps + anisotropie), découpe un rectangle arrondi anti-aliasé, puis le fond dans la photo en lumière linéaire : ombres (multiplication par l'éclairage adouci de la surface, qui ne fait qu'assombrir), reflets (*screen* de ce qui dépasse le noir de l'écran), teinte ambiante, grain. Le format réel de la zone est estimé par la méthode de Zhang & He (focale déduite des points de fuite). La détection au double-clic combine deux sources de candidats — une région de couleur proche qui croît autour du clic, et des quadrilatères formés par les droites de l'image (transformée de Hough votée par la direction du gradient, droites globales et proches du clic) — puis les note : part de chaque côté posée sur un vrai bord, régularité de la bande juste à l'extérieur (bordure, cadre, mur), cohérence des bandes intérieure et extérieure, vraisemblance géométrique d'un rectangle en perspective. Entre deux zones emboîtées, un anneau uniforme (bordure d'écran, cadre) fait préférer l'intérieur ; un anneau chargé (contenu d'une page) fait préférer l'extérieur. Les meilleurs candidats sont recalés au sous-pixel et proposés dans l'ordre. Pour masquer le contenu d'origine, l'éclairage de la surface est modélisé par une fonction quadratique du log de la luminance, ajustée de façon robuste (Tukey) : le contenu est rejeté comme aberrant, seule la lumière reste ; une mesure des détails fins et de la couleur décide si la surface est vierge.
- **Variantes et lots** : une variante est un « look » (fond, décor, lumière, caméra, sol, angle et finition de chaque appareil) tiré d'une graine. Les rendus se font dans un bac à sable : le projet est modifié temporairement hors historique et hors sauvegarde automatique, chaque look est préchargé (matières, HDRI, motifs) puis rendu par le moteur d'export, et le projet comme la vue de la caméra sont restaurés à l'identique. Le ZIP est écrit sans dépendance (`src/lib/zip.ts`, entrées stockées : les images sont déjà compressées).
- **Vidéo** : chaque animation est une fonction du temps (`src/animation/animations.ts`) : des images clés de caméra autour du sujet (azimut, élévation, distance, roulis, focale — le Vertigo garde la taille du sujet en reculant —, ouverture et mise au point) avec des courbes de type motion control, des mouvements d'objet (rotation avec dépassement, chute avec rebond amorti) et un montage en fondus. En qualité Cinéma, chaque image moyenne plusieurs instants pris dans un obturateur à 180° (de 3 à 10 selon la vitesse du mouvement), avec un échantillon de lentille différent à chaque instant ; chaque image est rendue hors ligne à son instant exact (aucune capture d'écran, donc aucune image perdue quelle que soit la machine), dans le bac à sable des variantes, puis encodée par **WebCodecs** via [Mediabunny](https://mediabunny.dev) (MP4 H.264 ou WebM VP9) ou quantifiée en GIF par [gifenc](https://github.com/mattdesl/gifenc). Les encodeurs ne se chargent qu'au premier export vidéo.
- **Export** : rendu hors écran à 2× la taille finale, découpé en tuiles (`camera.setViewOffset`) avec marges de recouvrement pour éviter les coutures, puis réduit. Le fond est peint par le même code dans l'aperçu et dans l'export (`src/lib/background.ts`), avec un léger dithering anti-banding sur les dégradés.

## Structure du code

```
src/
  app/          interface : barre du haut, bibliothèque, viewport, panneau de propriétés, raccourcis
  ui/           composants (Button, Slider, Segmented, Section…)
  i18n/         dictionnaires FR / EN
  store/        état du projet (zustand + historique zundo), assets, UI, toasts

  models/       un dossier par appareil + registre

  export/       réglages (résolutions, ratios, formats) et pipeline d'export
scripts/        captures de vérification Playwright, génération des exemples
```

## Ajouter un modèle

Chaque appareil est un module qui implémente `DeviceModule` (`src/models/types.ts`) :

```tsx
// src/models/tablet/TabletAir.tsx
import type { DeviceModule, DeviceProps } from '../types';
import { roundedSlab, roundedPlane } from '@/lib/geometry/sweep';
import { brushedMetal } from '@/scene/materials';
import { useScreenMaterial } from '@/scene/useScreenMaterial';

const W = 17.85, H = 24.76, T = 0.61; // centimètres (1 unité = 1 cm)

function TabletAir({ finish, surfaces, screen }: DeviceProps) {
  const screenMat = useScreenMaterial(surfaces.screen, 16.4 / 23.6, screen);
  // … construis la géométrie (mémoïsée) et retourne un <group>
}

export const tabletAir: DeviceModule = {
  id: 'tablet-air',
  name: { fr: 'Tablet Air', en: 'Tablet Air' },
  category: 'tablet',
  size: [W, H, T],
  surfaces: [{ id: 'screen', label: { fr: 'Écran', en: 'Screen' }, aspect: 16.4 / 23.6, nativeSize: [1640, 2360] }],
  finishes: [{ id: 'silver', name: { fr: 'Argent', en: 'Silver' }, swatch: '#d6d7da', colors: { frame: '#d6d7da' } }],
  defaultFinish: 'silver',
  Component: TabletAir,
};
```

Puis ajoute-le à `MODELS` dans `src/models/registry.ts`. Conventions :

- l'écran regarde vers **+Z** et la hauteur suit **+Y** ; avec `anchor: 'center'` (défaut) l'appareil est centré sur son origine et posé au sol automatiquement, avec `anchor: 'bottom'` (laptops, écrans) il repose déjà sur y = 0 ;
- `params` déclare des réglages (`slider`, `toggle`, `choice`, `text`) que le panneau de propriétés affiche tout seul ; `ORIENTATION_PARAM` ajoute portrait/paysage ;
- `view` donne le point visé et la direction de la caméra ; la distance est calculée automatiquement ;
- les pièces communes (objectifs, flash, perçages) sont dans `src/models/shared/parts.tsx`, les familles paramétrables dans `phone/Phone.tsx`, `tablet/Tablet.tsx`, `laptop/Laptop.tsx` ;
- les écrans utilisent `useScreenMaterial` (couleurs exactes, reflets de vitre) ; les objets imprimés utilisent `usePrintMaterial` (`src/models/print/shared.tsx`), un vrai matériau papier / céramique éclairé par la scène, et déclarent `surfaceKind: 'print'` ;
- un modèle peut avoir plusieurs `surfaces` (recto, verso, couverture…) : l'interface affiche une image par face ;
- `sizeFor(params)` donne l'encombrement selon les réglages (format, présentation) pour le cadrage automatique ;
- les géométries sont construites une seule fois et partagées entre instances.

## Déployer sur GitHub Pages

1. Pousse le dépôt sur GitHub (branche `main`).
2. Dans **Settings → Pages**, choisis **Source : GitHub Actions**.
3. Le workflow `.github/workflows/deploy.yml` construit et publie le site à chaque push sur `main`, à l'adresse `https://<utilisateur>.github.io/<dépôt>/`. Le chemin de base est déduit automatiquement du nom du dépôt.

Pour un autre hébergeur statique : `BASE_PATH=/ npm run build` puis publie `dist/`.
